# 지도 버스 운전게임

## 폴더 구조
```
index.html          게임 본체
car/                버스 정의 (JSON)
  index.json        초기화면에 보여 줄 버스 파일 목록
  aerocity-low.json
  aerocity-high.json
route/              노선 (구글어스 KML)
  index.json        초기화면에 보여 줄 노선 파일 목록
  2416.kml
```
GitHub Pages는 폴더 안의 파일 목록을 읽을 수 없어서, 새 파일을 넣으면 `index.json`에도 파일명을 한 줄 추가해야 해요.

## 버스 추가·수정 (car/*.json)
1. 기존 JSON을 복사해 새 이름으로 저장하고 값을 고칩니다.
2. `car/index.json`에 파일명을 추가합니다.

빠진 항목은 기본값으로 채워져요. 항목 설명:

| 항목 | 설명 |
|---|---|
| name | 초기화면에 표시되는 이름 |
| transmission | `auto`(자동) 또는 `manual`(수동, 클러치·E/Q 변속) |
| wheelbase / maxSteer / latLimit | 축거(m) / 최대 조향각(도) / 선회 시 허용 횡가속도(m/s²) |
| seats / capacity | 좌석 수 / 승객 정원 |
| gearLimit | 기어별 한계 속도(km/h), 첫 값 0은 중립 자리 |
| gearRec | 기어별 권장 속도 구간(km/h). 자동 변속 기준 |
| gearAcc | 기어별 최대 가속도(m/s²) |
| reverseLimit | 후진 한계 속도(km/h) |
| idle / redline | 엔진 공회전 / 한계 회전수(rpm) |
| brake.service / brake.full | 일반 브레이크 / 풀 브레이킹 감속(m/s²) |
| brake.airLag / brake.fullLag | 공압 지연(초) |
| retarder.decel | 리타더 단계별 감속(m/s²). 첫 값 0 = OFF. 없으면 `null` |
| doorTime | 문이 열리고 닫히는 시간(초) |

gearLimit, gearAcc, gearRec는 항목 수가 같아야 해요.

## 노선 추가 (route/*.kml)
- 구글어스에서 노선을 만들어 KML로 저장해 `route/`에 넣고, `route/index.json`에 파일명을 추가합니다.
- 노선은 두 가지 방식 모두 지원해요.
  - **선 + 점**: 경로(선)로 노선을 그리고, 위치표시(점)를 정류소로 찍기. 선은 실선으로 표시돼요.
  - **점만**: 선 없이 위치표시(점)만 순서대로 찍기. **KML에 저장된 순서(구글어스 장소 목록의 순서)** 대로 점을 이은 점선 안내선이 그려지고, 점이 2개 이상이어야 해요.
- 파일명은 `노선번호(방향).kml` 형식으로 지으세요. 예: `2222(강남방면).kml`, `2222(차고지방면).kml`
- 정류소 이름은 위치표시의 이름이에요. 이름을 안 붙이면 `정류소 N`으로 표시돼요.

### 차고지
- **회차 정보(설명에 "회차점"/"회차지")가 있는 KML은 첫 번째 장소가 차고지**예요. 정류소가 아니라서 승하차가 없고, 게임은 거기서 시작해요.
- 이름이나 설명에 "차고"가 들어간 장소는 위치와 상관없이 차고지로 봐요 (정류소 아님).
- 차고지가 없으면 첫 장소(점 노선은 첫 점, 선 노선은 선의 시작점)에서 시작하고, 그 장소가 정류소면 바로 승차할 수 있어요.

### 회차지(종점)
- 정류소의 **설명**에 `회차점`(또는 `회차지`)이라고 적으면 그 정류소가 회차지예요.
- 회차지에서는 **탑승객이 전원 내리고**, 대기 중인 승객이 **탈 수** 있어요.
- 도착 당시 승객이 모두 내린 뒤 문을 닫으면, **같은 번호의 다른 방향 파일**로 자동 전환돼요. 그 사이 탄 승객은 그대로 타고 가고, 같은 자리의 새 노선 첫 정류소는 이미 처리된 것으로 봐요.
- 같은 번호의 다른 방향 파일이 없으면 전환 대신 안내만 떠요.

## 조작
W/S 가속·브레이크, A/D 조향, Space 비상브레이크, F 앞문, G 뒷문, P 주차브레이크, R/T 리타더(있는 버스), Shift+E/Q 변속(수동 버스), Z/X 지도 확대·축소, / 정지화면


## 엔진 사운드 (초기 구현)
- `sound-engine.js`가 Web Audio API로 엔진 루프 샘플을 재생합니다.
- 차량 JSON의 `sound.engine`에 사운드 프로필 ID를 지정합니다. 현재 포함된 프로필은 `q290-euro6`입니다.
- `Sound/Q290 Euro6/`에는 `Sound_Q290(Euro6).cfg`에서 참조되고 ZIP에 실제 존재하는 6개 WAV만 복사했습니다.
- 원본 CFG의 `301low3.wav` 참조 파일은 ZIP에 없어 제외했습니다.
- 현재 두 에어로시티 차량에 연결된 Q290 Euro6 프로필은 **작동 확인용 임시 연결**입니다. Q290 엔진이 실제 에어로시티의 엔진이라는 뜻은 아니며, 차량별 정확한 엔진 사양이 확인되면 JSON의 `sound.engine`을 교체해야 합니다.
- 게임 출발 버튼을 누를 때 오디오를 활성화하며, 설정에서 엔진음 음량을 조절할 수 있습니다.
- GitHub Pages에 배포할 때 `sound-engine.js`, `Sound/`, `car/`를 함께 올려야 합니다.


## 사운드 시스템 (업데이트)

- 고상 수동 차량: 기존 Q290 Euro6 엔진음 유지
- 저상 자동 차량: Q290 Euro4~5 설정의 GE11 CNG 엔진 샘플 사용
- 하차벨: `Sound/stop.wav` (원본 OMSI 설정의 `haltewunsch_stop` 이벤트 참조)
- 앞문/뒷문: D92 계열 개폐 음원 연결
- 리타더: `retarderfolyamat.wav` 반복 재생, 작동/해제 시 `Retarder.wav` / `Retarder_aus.wav` 효과음
- 저상 차량 레드존 경고음은 미적용

사운드는 브라우저 Web Audio API로 재생됩니다. 첫 게임 시작 버튼을 눌러 오디오를 활성화합니다. 실제 브라우저에서 음향을 청취하는 테스트는 별도 확인이 필요합니다.


## 차량별 사운드 구성 (v5)

- `Sound/aerocity-low/`: 저상 자동 차량 엔진음 및 D92 도어음, 리타더, 파킹브레이크
- `Sound/aerocity-high/`: 고상 수동 차량 Q290 Euro6 엔진음, Euro6 앞문음, D92 뒷문음, 파킹브레이크, 레드존 경고음
- 파킹브레이크는 `P` 키 체결/해제에 연결됩니다. 레드존 경고는 고상 수동 차량에서만 회전수 2,522rpm(설정 레드라인의 97%)부터 재생됩니다.


## 차량별 사운드 설정 (v6)

모든 차량 사운드 파일 경로와 효과음 연결은 각 `car/*.json`의 `sound` 항목에서 관리합니다.

- `sound.engine`: `sound-engine.js`에 정의된 엔진 프로필 ID
- `sound.folder`: `Sound/` 아래 해당 차량 사운드 폴더 이름
- `sound.effects`: 하차벨, 앞·뒷문, 파킹브레이크, 리타더, 레드존 음원의 폴더 기준 상대 경로
- `sound.redzone.threshold`: 계기판 RPM 막대가 빨간색으로 바뀌는 기준. 기본값 `0.88`이며 계기판과 동일한 `rf > 0.88` 조건으로 재생합니다.

예를 들어 음원을 교체할 때는 지정된 차량 폴더 안의 파일을 같은 이름으로 덮어쓰거나, 다른 파일명을 사용한다면 JSON의 해당 경로도 함께 바꾸면 됩니다. 경로는 `Sound/<sound.folder>/<sound.effects 항목>` 순서로 결합됩니다.

레드존 경고음은 계기판 색상이 빨간색으로 바뀌는 즉시 반복 재생하고, 빨간색에서 벗어나면 페이드 없이 즉시 정지합니다. 이 설정은 `sound.effects.redzone`이 지정된 차량에만 적용됩니다.


## 3D 내비게이션 지도 및 정류장 좌표 보정 (지도 개편 1차)

- 지도 엔진은 기존 MapLibre GL JS + OpenFreeMap Liberty를 유지합니다.
- 운행 중 카메라는 버스 좌표를 중심으로 따라가며, 진행 방향에 맞춰 회전하고 약 54도 기울어집니다.
- OpenFreeMap 벡터 타일의 `building` 레이어를 이용해 건물을 입체적으로 표시합니다. 건물 높이 정보가 없는 곳은 기본 높이로 표시될 수 있습니다.
- 기존 KML의 정류장 Point는 계속 사용합니다.
- 정류장 위치 보정은 `route/stop-corrections.json`에서 관리합니다. KML 원본은 수정하지 않습니다.

보정 파일 예시:

```json
{
  "2416.kml": {
    "0": { "lng": 127.10275, "lat": 37.61360 },
    "1": { "lng": 127.10101, "lat": 37.61048 }
  }
}
```

객체의 키 `0`, `1`은 해당 KML의 Point가 기록된 순서(0부터 시작)입니다. 보정 좌표는 `[경도, 위도]`에 해당하며, 실제로 보정할 정류장만 입력하면 됩니다. 빈 객체 `{}`이면 모든 정류장은 KML 원본 좌표를 사용합니다.

- 이번 단계에서는 기존 KML LineString을 경로 표시 및 기존 진행 판정용으로 보존했습니다. 실제 도로망에 맞춘 경로 생성/스냅은 아직 적용하지 않았습니다.
- 실제 도로 경로를 적용할 때는 정류장 순서와 기존 차량 물리를 별도로 검증한 뒤 교체해야 합니다.
- 현재 게임의 버스 위치는 기존 주행 물리로 위경도를 갱신합니다. 따라서 3D 지도는 시각적 표현 및 방향 추적을 개선하지만, 아직 차량이 도로 중심선을 자동으로 따라가도록 강제하지는 않습니다.
